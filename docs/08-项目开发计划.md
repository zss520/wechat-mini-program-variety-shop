## 1. 计划原则

1. **先开业、后运营。** R1（交易上线）交付 P0：货架、下单、支付、自提核销、店铺配置、**核心漏斗埋点落库**。R2（运营包）交付 P1：热度看板、权重、首页推荐位、漏斗、订阅消息。
2. **埋点不后补。** `analytics_events` 与支付侧计销售必须随 **M3 交易域** 上线，不能等到 M7 再接。看板可以后做。
3. **三条轨道可并行，接口先行。** 服务端出契约 → 管理端与小程序按 mock/联调。阻塞点永远是：登录、商品读写、下单库存、支付回调。
4. **环境锁死。** 所有 `npm install` / `build` 在 **Node.js 16.17.0** 上验证；`admin` 使用 Vite 4.5.x + React 18 + MUI v5，禁止默认 Vite 5。
5. **小程序只走原生。** 不引入 uni-app / Taro。
6. **一期不上。** 拼团、秒杀、多门店、个性化模型、详情关联推荐、购物车凑单、会员积分券（P1 营销可放 R2 后半或 R3）。

两个发布切片：

| 切片 | 对应阶段 | 店主能做什么 |
|------|----------|----------------|
| **R1 交易上线** | M1–M6 | 上架、收款、备货、核销自提；系统开始记曝光/点击/支付 |
| **R2 运营包** | M7 | 看热度/CTR/购买率，调权重和首页推荐位 |

R1 是开业门禁；R2 是 G6「用数据摆货架」的完成态。P2 不进本计划实施队列。

## 2. 工作流与仓库

```
docs/           已存在，本阶段只维护
miniprogram/    微信原生（TS 优先）
admin/          Vite4 + React18 + MUI v5
server/         Node 16.17.0 + Express + TS + MySQL
```

建议 **一个 git 仓库、三个包**，根目录 `engines.node = 16.17.0`。各自 `package-lock.json`。无根 workspace 工具链要求（避免 pnpm 在 Node 16 上的变数），用 npm。

### 2.1 三条轨道

| 轨道 | 职责 | 主要产出 |
|------|------|----------|
| **S 服务端** | 表结构、REST、微信登录/支付、库存事务、事件接收、定时任务 | `/api/app` `/api/admin` `/api/pay` |
| **A 管理端** | 店主后台 | 登录、商品、订单、配置、R2 分析与推荐位 |
| **P 小程序** | 顾客端 | 浏览、交易、履约展示、tracker |

合规（营业执照、类目、商户号、隐私协议）与研发 **并行**，不阻塞 M1–M5 开发版联调。

### 2.2 依赖总图

```
M0 文档 ──► M1 骨架（三端空跑 + 库表最小集）
              │
              ▼
            M2 商品域 ◄── 上传与分类
              │
              ▼
            M3 交易 + P0 埋点 + 支付回调     ◄── 商户号可后补沙箱
              │
              ▼
            M4 履约（自提码 / 核销 / 配送状态）
              │
              ▼
            M5 店铺配置与轮播
              │
              ▼
            M6 R1 打磨上线（HTTPS、审核、备份）
              │
              ▼
            M7 R2 运营包（看板、热度、权重、推荐位）
```

**不可颠倒：** M3 之前不要做支付页的「假成功」。**可并行：** M2 期间 A 做商品表单、P 做静态页；M4 与 M5 在 M3 主路径稳定后可两轨并行。

### M1 工程骨架

**目标：** 三端在 Node 16.17.0 上可启动；目录与依赖锁定；最小鉴权打通。

**S**

- Express + TS 工程：`tsc` 出 JS，`ts-node-dev` 仅开发。
- MySQL 连接；迁移工具选 **knex**（避免 Prisma 引擎与 Node 16 不匹配）。
- 建表最小集：`admin_users` `users` `shop_settings`（KV 即可）。
- `POST /api/admin/auth/login`、JWT 中间件、`GET /api/app/shop/bootstrap`（可先写死店名）。
- `.env.example`；Helmet / CORS 白名单雏形。

**A**

- Vite 4.5.x、`engines.node=16.17.0`、React 18.2、MUI 5.15、Router 6。
- `AdminLayout`（Drawer + AppBar）、`/login`、登录后空工作台。
- Axios 拦截器挂 Bearer；401 跳登录。
- `npm run build` 在 16.17.0 零错误（**本阶段硬门禁**）。

**P**

- 微信开发者工具导入；`app.ts` / `app.json`；TabBar：首页、分类、购物车、我的。
- 空页面占位；`services/request.ts` 读 `bootstrap`。
- `project.config.json` 基础库 ≥ 2.32.0；TypeScript + `miniprogram-api-typings`。

**横切**

- README 增加本地启动步骤（nvm use 16.17.0）。
- 可选：CI 用 `node:16.17.0` 跑 admin/server build。

**退出条件**

- [ ] 三端启动无报错
- [ ] admin 登录成功进入布局
- [ ] 小程序能拉到 bootstrap
- [ ] Node 16.17.0 下 admin/server 构建通过

### M2 商品域（云货架）

**目标：** 店主可上架，顾客可浏览/搜索。无支付。

**S**

- 表：`categories` `goods`（含 `manual_weight` `heat_score` 字段 **先建默认 0**，本阶段排序可用 `sort`）。
- 预建（可空写入）：`analytics_events` `goods_stats_daily` `recommend_slots` `recommend_slot_items`，避免 M3/M7 再改迁移。
- API：分类 CRUD、商品 CRUD、软删、上下架、`POST /uploads/image`。
- `GET /api/app/categories` `GET /api/app/goods` `GET /api/app/goods/:id` `GET /api/app/home`（轮播可空、推荐暂按 sort/销量）。

**A**

- `/categories` `/goods` `/goods/new` `/goods/:id`
- 列表筛选、上下架、图片上传、表单校验（规格 3.4 节）。

**P**

- 首页：搜索条、分类导航、商品网格（推荐区先用同一列表接口）。
- 分类页、搜索页、详情页（步进器、售罄）。
- 统一商品卡组件（M3 埋点挂在此组件，M2 即可抽组件）。

**退出条件**

- [ ] 管理端新增上架商品，小程序详情可见
- [ ] 下架/售罄规则符合规格
- [ ] 图片上传与展示 HTTPS 可用（开发可用本地静态）

### M3 交易域 + P0 埋点（关键路径）

**目标：** 闭环「加购 → 下单 → 微信支付 → 库存预占/释放」；事件落库；支付成功由服务端计销售。

拆成 **M3a 订单库存** 与 **M3b 支付与埋点**，顺序不可反，可在 M3a 用「模拟支付成功」仅限开发开关且不得带入 R1。

#### M3a 购物车与订单

**S**

- 表：`cart_items` `addresses` `orders` `order_items` `order_logs` `payments`。
- 事务下单：`WHERE stock >= qty` 扣减；取消/超时加回。
- API：购物车、地址、preview、创建订单、订单列表/详情、取消、关单任务（`node-cron`）。
- 状态机按规格第 4 章；非法流转 409。

**A**

- `/orders` 列表 + 详情（本阶段只读查看即可，备货按钮可进 M4）。
- 工作台待付款/待备货数量可选。

**P**

- 登录：`wx.login` + 手机号绑定（下单前必须）。
- 购物车、确认订单（自提/配送）、订单列表/详情、待付款继续支付入口（支付参数 M3b）。

#### M3b 支付与埋点

**S**

- 微信统一下单、APIv3 回调验签、幂等更新 `PENDING_PACK`。
- `POST /api/app/events`：枚举校验、批量 insert、限流、剥离 PII。
- 支付成功循环 `order_items` 更新当日 `goods_stats_daily` 的 pay_*（或写内部事件再汇总）。
- 开发：沙箱 / 测试商户；回调内网穿透或微信开发文档允许的调试验证。

**P**

- `utils/tracker.ts` 队列 + flush；`app_launch/show/hide` `page_view`。
- 商品卡 IntersectionObserver：`goods_expose` / `goods_click`；详情 `goods_detail_view`。
- 加购成功、下单成功、`pay_invoke` / `pay_result`。
- query 带 `slot` `pos`（首页先写 `home_recommend` 或 `category_list`）。

**A**

- 无需分析页；不要阻塞本阶段。

**退出条件**

- [ ] 真支付或沙箱支付成功后订单进入待备货，库存已减
- [ ] 待付款超时关单，库存恢复
- [ ] 待备货取消走退款（沙箱）并恢复库存
- [ ] 并发库存：1 件库存两单只有一单成功（接口或单测）
- [ ] `analytics_events` 有曝光/点击/详情/加购/下单
- [ ] 杀小程序后支付成功，日统计 pay_qty 仍增加
- [ ] 顾客 token 无法调用 `/api/admin`

### M4 履约域

**目标：** 店主按单作业：备货、自提核销、配送状态。

**S**

- `pickup_code` 生成规则；`pack` / `pickup` / `deliver/start` / `deliver/complete` / 店主取消退款。
- 核销校验码与状态。

**A**

- 订单行操作随状态变化；核销输入框默认带出该单码。
- 侧栏待备货 + 待自提 Badge。

**P**

- 详情大号提货码、状态文案、联系店主、进行中不可自助取消。

**退出条件**

- [ ] 自提：支付 → 备货 → 待自提 → 核销 → 已完成
- [ ] 配送：备货 → 待配送 → 配送中 → 送达
- [ ] 错误提货码有明确失败提示

### M5 配置与内容

**目标：** 换店名即可「像这家店」；轮播可配。

**S / A**

- `GET/PUT /settings`：店名、Logo、电话、微信、自提地址、营业时间、配送开关与运费、超时分钟、暂停接单。
- Banner CRUD，启用最多 5 条。
- 暂停接单：浏览可以、下单 409。

**P**

- bootstrap 驱动导航标题、履约提示条、联系店主。
- 轮播点击跳转；无图隐藏。

**退出条件**

- [ ] 改店名/电话后小程序 TTL 内生效（设置接口勿与推荐长缓存混用）
- [ ] 关配送后确认订单仅自提
- [ ] 暂停接单无法提交订单

### M6 R1 打磨与上线

**目标：** 可提交微信审核并部署管理端。不做新功能，只补门禁。

**工作包**

- 隐私协议、隐私接口声明（登录、手机号、分析数据用途）。
- 合法域名 HTTPS、ICP；Nginx：`/admin` 静态、`/api` 反代。
- 支付进件绑定 appid；正式回调 URL。
- 备份 `mysqldump` 日任务；日志脱敏抽查。
- 体验：字号、售罄、空态、弱网 Toast（规格第 8 章）。
- 安全：管理端不公开收录、改密、上传类型限制。
- Node 16 EOL：防火墙 / 仅店主使用管理端；技术债记录「升级 Node 18」但不在 R1 实施。

**退出条件（R1 Go-Live）**

对齐 [06 第 6 节](./06-非功能需求与实施计划.md) 清单中除 P1 运营包外的全部项。P1 看板 **不是** R1 硬门槛。

### M7 R2 运营包

**目标：** 店主能看过程指标并干预货架。依赖 M3 已积累的事件；若 R1 未采数，本阶段无法「补历史」。

**S**

- 日批 00:20：汇总 `goods_stats_daily`、重算 `heat_score`。
- `GET /reports/goods` `/reports/funnel` `/reports/signals`
- `PATCH /goods/:id/weight`、批量加权
- 推荐位 GET/PUT + preview；`GET /home` 按 `PIN_THEN_HEAT` 填充
- 列表 `sort=composite`：`heat_score + manual_weight`，售罄沉底，新品 72h +8
- 可选：`wx.reportEvent` 双写（不阻塞）

**A**

- `/reports` 漏斗、`/reports/goods` 分析表、`/contents/recommends` 置顶与预览
- 商品列表可选列：热度、CTR、购买率、行内加权
- 样本不足展示「— / 样本少」

**P**

- 首页推荐模块走真实推荐接口；点击带 `slot` `pos`
- 分类默认综合排序；顾客端不出现「热度」字样
- 无推荐商品则隐藏整块

**退出条件**

- [ ] 文档 07 第 9.2 节验收用例全部通过
- [ ] 预览与小程序前 N 个置顶一致
- [ ] 加权立即影响排序，无需等日批（热度仍可日批）

**R2 后置（仍属 P1，可再切片，不阻塞推荐位）：** 优惠券、限时特价、积分、库存预警、订阅消息（备货通知）。与推荐位无强依赖，可按店主意愿排队。

## 6. 质量门禁（每阶段合并前）

2. **接口：** 变更同步 `docs/05`；app/admin 路径隔离。
3. **金额：** 分存储；下单金额服务端重算。
4. **库存：** 条件更新，禁止先读后写无事务。
5. **埋点（M3 起）：** 主路径事件可查；payload 无手机号/openid。
6. **文档：** 行为与 PRD/规格冲突时改文档或改代码，禁止只改一处。

## 8. 建议的开工第一批提交（M1）
