## 1. 行业背景与宏观环境

### 1.1 社区零售市场概况

2026 年，中国社区零售市场规模已突破 **3.8 万亿元**，预计到 2030 年稳步增长至 **6.2 万亿元**，年均复合增长率约 **8.5%**。全球社区商业市场规模已突破 3.8 万亿美元；中国市场渗透率从 2020 年的 18% 跃升至 2026 年的 **37%**。社区便利店、生鲜电商、邻里中心等业态持续扩张。

社区商业消费呈现 **高频化、即时化**：

- 生鲜品类占比约 **31%**
- 日用快消品占比约 **28%**

社区便利店凭借距离近、品类够用、服务灵活，已成为居民日常生活的重要组成部分。对独立杂货铺而言，核心不是与平台拼 SKU 广度，而是把「门口那家店」的信任关系数字化。

### 1.2 微信小程序生态现状

微信小程序是中国最大的私域经营阵地。截至 2026 年第一季度：

| 指标 | 数据 |
|------|------|
| 日活跃用户 | 7.1 亿 |
| 月活跃用户 | 10.5 亿 |
| 全网小程序交易规模 | 1.5 万亿元（同比 +28.7%） |
| 全网商城小程序数量 | 突破 380 万个 |
| 零售行业商家小程序渗透率 | 74.3% |
| 电商类小程序交易规模 | 5800 亿元（同比 +38.1%） |

结论：私域电商已从「可选经营模式」转为实体店的「生存刚需」。消费者的小程序购物习惯已经形成，社区杂货铺接入小程序的教育成本显著低于 2020 年前后。

对本项目的含义：

- 顾客端必须做 **微信小程序**，而不是独立 App。
- 流量来源以店内扫码、微信群链接、老客转发为主，而不是依赖公域投放。
- 支付、订阅消息、分享卡片均应使用微信原生能力，降低转化损耗。

### 1.3 政策环境

政策层面对社区商业数字化形成结构性支撑：

- 商务部等 9 部门《关于加快零售业创新发展的意见》：支持商业设施数智化改造，提升社区商业。
- 多地推进「15 分钟便民生活圈」，支持通过小程序、App 等为居民提供便民服务。
- 部分地方政府（如广东）明确支持个体工商户应用社区电商、社交电商，实现线上线下融合。

对本项目的含义：产品叙事可对齐「便民生活圈 / 社区数字化」，但功能设计仍以店主可独立运营为准，不依赖政府补贴或平台补贴。

## 2. 目标市场分析

### 2.1 市场规模与增长潜力

| 指标 | 数据 / 判断 |
|------|-------------|
| 即时零售 | 2024 年约 7810 亿元；2026 年将突破 1 万亿元；2030 年预计约 2 万亿元 |
| 社区便利店 | 规模稳步增长，数字化渗透率持续提升 |
| 社区类小程序 | 高频刚需场景，年均增速约 23% |
| 接入小程序的便利店 | 平均客单价可提升 15%–30%（行业观察，非本产品承诺） |

### 2.2 细分市场定位

本产品属于 **社区零售数字化** 细分赛道，特征如下：

| 维度 | 定义 |
|------|------|
| 业态 | 社区杂货铺 / 便利店 / 日用百货 / 小型超市 |
| 购买频次 | 日用消费品，高频刚需、复购强 |
| 服务半径 | 社区周边 **1–3 公里** |
| 客群 | 以本社区居民为主，邻里关系稳定 |
| 履约 | 「即买即用」：到店自提优先，店主配送补充 |
| 经营规模 | SKU 约 200 以内、月营收约 50 万以下（一期默认） |

**明确不做的市场（一期）：**

- 与美团闪购 / 淘宝闪购正面比拼全城即时配送
- 多仓多城的连锁中台
- 社区团购（预售 + 次日自提点）作为主模式
- 跨境、品牌旗舰、直播带货中台

## 3. 竞争格局分析

### 3.1 宏观竞争环境

即时零售已形成「双寡头」：美团闪购与淘宝闪购主导规模化履约。社区团购因履约不稳、价格战反噬供应链等原因基本退潮。

这给独立社区杂货铺留下窗口期：

- 大平台聚焦规模与时效，抽成与配送成本高。
- 社区小店可用「熟人经济 + 数字化」建立差异化，顾客资产归商家自己。

### 3.2 竞品对比

| 维度 | 大型平台（美团 / 淘宝闪购） | 连锁便利店（美宜佳等） | 独立杂货铺小程序（本产品） |
|------|---------------------------|----------------------|---------------------------|
| 商品丰富度 | 极高 | 中高 | 中等，聚焦本店真实库存 |
| 配送时效 | 约 30 分钟 | 约 30–60 分钟 | 灵活：自提即时 / 店主配送 |
| 客单价 | 中高 | 中等 | 中低，高频低客单 |
| 用户关系 | 交易关系 | 品牌关系 | 邻里信任关系 |
| 运营成本 | 高（抽成 + 配送） | 中 | 低（无平台抽成） |
| 顾客资产 | 归平台 | 归连锁品牌 | **归本店** |

### 3.3 差异化机会（产品必须兑现）

1. **邻里信任**：多年积累的人际关系，平台无法替代；产品要用「自提码、店主电话、熟悉的商品名」强化这种关系，而不是做成冷冰冰的电商壳。
2. **零平台抽成**：避开外卖 / 闪购 15%–20% 佣金；支付通道费需在技术方案中单独核算。
3. **灵活履约**：到店自提 + 店主配送，成本可控；一期不强制对接第三方运力。
4. **私域沉淀**：会员、订单、优惠券在自有系统，可被微信群与订阅消息反复触达。

## 4. 目标用户分析

### 4.1 顾客画像

| 用户类型 | 年龄 | 特征 | 核心需求 | 对产品的要求 |
|---------|------|------|---------|--------------|
| 社区家庭主妇 / 主夫 | 30–50 | 日常采购决策者，重性价比 | 便捷下单、优惠信息、快速拿到货 | 分类清晰、特价醒目、自提方便 |
| 社区上班族 | 25–40 | 忙碌，追求效率 | 线上下单、下班自提或配送 | 路径短、支付快、订单状态清楚 |
| 社区老年人 | 60+ | 习惯到店，逐步接受线上 | 操作简单；子女或店主可代劳 | 大字号、按钮大、可电话联系店主 |
| 社区年轻租客 | 20–30 | 熟悉移动支付 | 即时买、新品、会员优惠 | 分享、复购、优惠券 |

### 4.2 店主画像（付费决策者）

| 项 | 描述 |
|----|------|
| 身份 | 个体店主或店长，一人多岗（进货、收银、备货、送货） |
| 数字化能力 | 会用微信、收付款码；不熟悉复杂中台 |
| 设备 | 店内 Android / Windows 电脑或平板；手机随时处理订单 |
| 核心诉求 | 少接微信私聊、少记错单、库存别卖超、老客能召回 |
| 不可接受 | 学习成本高、插件多、年费不透明、必须自己运维服务器 |

管理端必须用 **Material UI 标准后台布局**（侧栏 + 顶栏 + 表格 + 表单），信息密度高于小程序，但交互保持「非技术人员可独立完成日常操作」。

### 4.3 顾客痛点 → 功能映射

| 痛点 | 对应能力 | 优先级 |
|------|----------|--------|
| 不知道店里有什么、什么价 | 云货架：分类、搜索、详情、库存状态 | P0 |
| 微信群问价、私聊下单、手工记账 | 购物车 + 在线下单 + 微信支付 | P0 |
| 老客买过后无人触达 | 会员、优惠券、订阅消息（P1） | P1 |
| 不想出门时买不到 | 配送到家 + 自提码 | P0 |
| 促销信息分散 | 首页轮播、特价专区、优惠券 | P0 / P1 |

### 4.4 店主痛点 → 功能映射

| 痛点 | 对应能力 | 优先级 |
|------|----------|--------|
| 漏单、错单、重复确认 | 订单列表、状态流转、新订单提醒 | P0 |
| 改价、上下架靠口头 | 商品 CRUD、上下架、分类 | P0 |
| 不知道什么好卖 | 销售概况、热销榜（P1） | P1 |
| 优惠靠口头承诺 | 优惠券、限时特价（P1） | P1 |
| 打印小票、对账麻烦 | 订单打印（P1）、订单金额统计 | P1 |

## 5. SWOT 分析

| 优势（S） | 劣势（W） |
|-----------|-----------|
| 邻里信任深 | 店主数字化能力弱，后台必须「开箱即用」 |
| 无平台抽成 | SKU 有限，不能做成综合商城 |
| 经营灵活、决策快 | 配送运力弱，必须以自提为主 |
| 位置就在社区门口 | 品牌认知限于本小区 |

| 机会（O） | 威胁（T） |
|-----------|-----------|
| 小程序生态成熟、获客成本相对可控 | 美团 / 淘宝闪购持续下沉 |
| 政策支持社区数字化 | 连锁便利店加密布点 |
| 消费者已习惯小程序购物 | 同类模板小程序增多 |
| 私域工具（群、订阅消息）成熟 | 用户习惯多平台比价 |

**产品策略含义：**

- 用「本店真实库存 + 自提 + 店主可联系」对抗平台「更全、更快」。
- 用极简后台对抗店主不会用系统的劣势。
- 一期不做过度营销玩法（拼团 / 秒杀为 P2），避免运营负担反噬。

## 6. 市场结论与对本项目的约束

1. **要做小程序，而且要做原生。** 微信是私域主阵地；原生能力（支付、订阅消息、分享、码）最稳，也符合本仓库「微信原生」技术决策。
2. **小程序成功不靠技术炫技，靠把邻里关系数字化。** 功能以货架、订单、履约、会员为主，拒绝一期做成「全功能电商中台」。
3. **管理端必须是店主能用的 Web 后台。** 选用 React + Material UI，保证表格、筛选、表单的专业度；锁定 Node 16.17.0，保证目标服务器 / 开发机可构建。
4. **履约以自提为核心路径。** 配送是增强，不是与闪购比 30 分钟。
5. **顾客资产必须自有。** 会员、订单、优惠在本系统，不依赖第三方 SaaS 锁死数据（一期即按自建系统设计，见技术方案）。

调研数据用于论证「为何做」与「做什么边界」，不作为对外承诺的经营指标。具体功能范围以 [产品需求文档](./02-产品需求文档.md) 为准。
