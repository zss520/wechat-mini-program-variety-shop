# 杂货铺微信小程序 · 技术架构与技术方案

| 项 | 内容 |
|----|------|
| 文档版本 | V1.1 |
| 强制约束 | 顾客端 **微信小程序原生**；管理端 **Vite + TypeScript + React + Material UI**；开发与构建适配 **Node.js 16.17.0** |

---

## 1. 总体架构

```
┌─────────────────┐     HTTPS + WSS(可选)      ┌──────────────────┐
│ 微信小程序原生   │ ◄────────────────────────► │  API 服务        │
│ WXML/WXSS/JS|TS │                            │  Node 16.17.0    │
└─────────────────┘                            │  Express + TS    │
                                               │                  │
┌─────────────────┐     HTTPS                  │  JWT / Session   │
│ 管理端 SPA      │ ◄────────────────────────► │  微信登录/支付   │
│ Vite4 React18   │                            │  事件接收/热度批  │
│ MUI v5          │                            └────────┬─────────┘
└─────────────────┘                                     ▼
                                               ┌──────────────────┐
                                               │ MySQL 8 / Redis  │
                                               │ 对象存储(图片)    │
                                               └──────────────────┘
                         微信支付、小程序码、订阅消息 ──► 微信开放平台
```

**原则：**

- 三份代码仓或 **monorepo**：`miniprogram/`、`admin/`、`server/`。
- 小程序 **不** 使用 uni-app、Taro、kbone。
- 管理端 **不** 使用 Vite 5/6 作为默认（Node 16 不支持）；**不** 默认升级 Material UI v6（降低工具链与 peer 风险）。
- 服务端与管理端构建均在 Node **16.17.0** 上验证。

## 3. Node 16.17.0 兼容性与版本锁定

> Node.js 16 已结束官方维护。本项目锁定 16.17.0 是 **环境约束**，不是推荐长期停留。升级 Node 18+ 前必须评估 Vite 5 与依赖。当前交付以 **可在 16.17.0 安装、开发、构建** 为准。

### 3.1 为何不能用「当前最新」前端栈

| 组件 | 最新主流 | 与 Node 16 关系 |
|------|----------|-----------------|
| Vite 5 / 6 | 要求 Node 18+ | **禁止** 作为本项目默认 |
| Vite 4.5.x | 支持 Node 14.18+ / 16+ | **选用** |
| MUI v6 | 前端库本身可运行，但生态常搭配 Vite 5 | **一期用 v5** |
| ESLint 9 | 扁平配置 + 较新 Node | **一期用 ESLint 8** |

### 3.2 管理端推荐版本（锁定区间）

在 `admin/package.json` 中声明：

```json
{
  "engines": {
    "node": "16.17.0",
    "npm": ">=8.15.0"
  },
  "private": true
}
```

Node 16.17.0 自带 npm 8.15.x。**使用 npm，不强制 pnpm/yarn**（pnpm 8 对 Node 16 需核对；为减少工具链风险默认 npm）。

| 依赖 | 推荐版本 | 说明 |
|------|----------|------|
| `vite` | `4.5.3`（4.5.x 最新补丁） | 构建工具 |
| `@vitejs/plugin-react` | `4.2.1` | React 插件，配合 Vite 4 |
| `react` / `react-dom` | `18.2.0` | 18.3 亦可，以 18.2 为稳妥 |
| `typescript` | `5.3.3` 或 `4.9.5` | 优先 5.3.3；若 CI 异常则降 4.9.5 |
| `@types/react` `@types/react-dom` | 与 React 18 对齐 | |
| `@mui/material` | `5.15.21` | Material UI v5 末代稳定线 |
| `@mui/icons-material` | `5.15.21` | |
| `@emotion/react` `@emotion/styled` | `11.11.x` | MUI 5 样式引擎 |
| `@mui/x-data-grid` | **一期不引入** | 用 Table 自研分页，避免许可与大版本 |
| `react-router-dom` | `6.22.0` | v6；不要默认 v7 |
| `axios` | `1.6.8` | HTTP |
| `dayjs` | `1.11.x` | 日期；避免 moment |
| `notistack` 或自封装 Snackbar | 可选 | |
| `@types/node` | `16.18.x` | 与运行时一致 |
| `eslint` | `8.57.x` | |
| `eslint-plugin-react` `eslint-plugin-react-hooks` | 8 生态 | |
| `prettier` | `3.2.x` 或 `2.8.8` | Prettier 3 需确认 Node 16；不行则 2.8 |
| `vite-plugin-checker` | 可选，注意 Node 16 | |

**Vite 配置要点：**

- `target`：`es2019` 或 `es2020`（勿上 esnext 导致旧 Chromium 管理端环境出问题）。
- 开发服务器 host `0.0.0.0` 便于内网。
- 环境变量前缀 `VITE_`；`VITE_API_BASE_URL`。
- 路径别名 `@` → `src`。

**TypeScript：** `compilerOptions.target` `ES2020`，`jsx` `react-jsx`，`strict` true。

### 3.3 服务端推荐版本（同一 Node）

| 依赖 | 推荐版本 |
|------|----------|
| `typescript` | 与 admin 相同 |
| `express` | `4.19.x`（Express 5 需单独评估） |
| `cors` `helmet` `morgan` | 4.x / 7.x / 1.x |
| `jsonwebtoken` | `9.x` |
| `bcryptjs` | `2.4.x`（纯 JS，避免 bcrypt 原生编译在 16 上的麻烦） |
| `mysql2` | `3.9.x`（核对 Node 16 支持，3.x 一般可以） |
| `zod` | `3.23.x` 做入参校验 |
| `multer` 或直传 OSS | 图片 |
| `axios` | 调微信 API |
| `dotenv` | `16.x` |
| 运行：`ts-node-dev` 或先 `tsc` 再 `node` | `ts-node` 在 16 上可用；生产用 `tsc` 出 JS |

ORM：**Prisma** 部分版本对 Node 16 已停止测试，**一期建议 `knex` + `mysql2` 或轻量 `kysely`**，避免 Prisma 引擎与 Node 16 不匹配。若团队强依赖 Prisma，必须在 16.17.0 上做安装冒烟后再写入 lock。

### 3.4 小程序技术

| 项 | 选型 |
|----|------|
| 语言 | **TypeScript**（微信开发者工具原生支持）或 JavaScript；推荐 TS + `miniprogram-api-typings` |
| 基础库 | 最低 **2.32.0**（覆盖登录、支付、隐私）；在 `project.config.json` 声明 |
| UI | 自研组件 + 少量原生组件；不引入 Vant 亦可，若引入 **Vant Weapp 1.11.x** 需确认无构建依赖 Node 18 |
| 状态 | 页面 data + 全局 `globalData`；购物车以服务端为准 |
| 请求 | 封装 `wx.request`，统一 baseURL、token、错误码 |
| 埋点 | `utils/tracker.ts` 批量上报；商品卡 IntersectionObserver；P1 双写 `wx.reportEvent` |
| 图片 | CDN / OSS URL，注意 https 与 download 合法域名 |

不使用 Skyline 作为一期必选（兼容性）；默认 WebView 渲染。

### 3.5 本地开发环境

1. 安装 **恰好** Node 16.17.0（nvm：`nvm install 16.17.0 && nvm use 16.17.0`）。
2. 微信开发者工具导入 `miniprogram/`。
3. `admin`：`npm install && npm run dev`（Vite 4 默认 5173）。
4. `server`：`npm install && npm run dev`（如 3000）。
5. 小程序开发版 request 合法域名在本地可勾选「不校验」。

CI 镜像：`node:16.17.0-bullseye`，`npm ci` 后 `npm run build`（admin + server）。

## 4. 管理端技术设计

### 4.1 技术栈职责

| 库 | 职责 |
|----|------|
| React 18 | UI；函数组件 + Hooks |
| React Router 6 | 路由、懒加载 `React.lazy` |
| MUI 5 | Button、TextField、Table、Drawer、Dialog、Snackbar、AppBar、CssBaseline |
| Emotion | MUI 默认样式；主题 `createTheme` |
| Axios | API；拦截器挂 Bearer Token |
| 自研 | 鉴权上下文 `AuthProvider`、`RequireAuth` |

### 4.2 主题

- `palette.primary` 与小程序品牌色接近（可配置静态常量，后期再做运行时换肤）。
- `typography.fontFamily`：`"Roboto", "PingFang SC", "Microsoft YaHei", sans-serif`。
- `shape.borderRadius` 8。
- 管理端以浅色为主，方便店主白天在店内使用；不做强制暗色一期。

### 4.3 鉴权

- 登录接口返回 `accessToken`（及可选 refresh）。
- `localStorage` 存储；Axios `Authorization: Bearer`。
- 401 清空并跳转登录。
- CSRF：纯 Bearer 可降低 CSRF；仍须 CORS 白名单。

### 4.4 构建产物

`vite build` 输出 `admin/dist` 静态文件，由 Nginx 托管，`try_files` 回 `index.html`。API 反向代理 `/api` → Node。

## 5. 小程序技术设计

### 5.1 分包（可选）

SKU 少、页面少，一期 **主包即可**。若主包超过 2MB，再拆订单与地址分包。

### 5.2 请求与域名

微信公众平台配置：

- request：API 域名
- uploadFile：OSS 或 API
- downloadFile：CDN
- 业务域名（web-view 一期不用可空）

### 5.3 支付

1. 服务端统一下单（`appid` + `mchid` + 商户密钥 / APIv3）。
2. 小程序 `wx.requestPayment`。
3. 支付结果回调验签，更新订单；小程序结果页再查一次订单状态（防回调延迟）。

### 5.4 登录

`POST /api/auth/wx-login { code }` → `{ token, user }`。

手机号：`POST /api/auth/wx-phone { code }`（手机号组件返回的 code）由服务端调微信接口解密 / 换号。

### 5.5 安全

- token 有效期（如 7 天）+ 失效可重登。
- 敏感接口校验用户只能访问自己的订单、地址、购物车。
- 管理端接口完全独立鉴权，禁止用顾客 token 调管理 API。

## 6. 服务端技术设计

### 6.1 分层

`routes → controllers → services → db`

校验：Zod schema 与路由绑定。

### 6.2 进程

Node 16 下用 `node server/dist/index.js`；可用 `pm2`（注意 pm2 版本对 Node 16）。单进程即可支撑 PRD 500 在线（实际瓶颈在 DB 与支付），预留反向代理。

### 6.3 文件存储

- 开发：本地 `uploads/` + 静态映射。
- 生产：阿里云 OSS / 腾讯云 COS，**密钥仅服务端**；管理端走「服务端签名直传」或「先上传 API 再回 URL」。

图片：限制 mime 与大小；可选服务端压缩（`sharp` 在 Node 16 需选用兼容 binary 的版本，否则跳过压缩只限大小）。

### 6.4 定时任务

- 待付款超时关单：每分钟扫 `PENDING_PAY` 且超时；可用 `node-cron`（注意与 Node 16 兼容的 3.x）。
- **热度与日统计：** 每日 00:20 汇总 `goods_stats_daily` 并重算 `heat_score`；支付回调增量更新当日支付指标。
- 事件明细超过 90 天删除或归档（可同机 cron）。

### 6.5 配置

环境变量（勿提交仓库）：

- `PORT` `DATABASE_URL` `JWT_SECRET`
- `WX_APPID` `WX_SECRET`
- `WX_MCHID` `WX_PAY_KEY` 或 APIv3 证书路径
- `ADMIN_PASSWORD_SALT` 等

### 6.6 埋点接入

见 [文档 07](./07-埋点与商品运营分析.md)。要点：`POST /api/app/events` 批量 insert、event 枚举校验、IP 限流、同匿名 ID 单日单商品曝光截断；购买转化只信支付回调。首页推荐接口缓存建议 ≤ 60s。

## 8. 部署拓扑（建议）

单机即可：

- Nginx：443 证书；`/admin` 静态；`/api` 反代；上传目录。
- Node API。
- MySQL 本机或同内网。

小程序后台配置服务器域名必须 **HTTPS + ICP**（国内）。

管理端仅店主使用，可另加 HTTP Basic 或 IP 白名单（P1）。

## 9. 与「SaaS 模板」的关系

市场调研原稿建议小店用 SaaS 快速上线。**本仓库按定制研发交付**，原因：

1. 顾客端指定微信原生，便于支付、审核与长期维护。
2. 管理端指定 React + MUI，店主得到完整数据所有权。
3. 文档与代码同库，后续迭代不绑定第三方模板协议。

若经营上需更快验证，可用 SaaS 并行试运营，但 **本项目实现范围仍以本文档为准**。

## 10. 质量与工程要求

| 项 | 要求 |
|----|------|
| 管理端 | `npm run build` 在 Node 16.17.0 零错误 |
| 服务端 | `tsc --noEmit` 通过 |
| 小程序 | 开发者工具体验评分基础项无阻塞；无未配置隐私接口 |
| 接口 | REST + JSON；错误 `{ code, message }` |
| 埋点 | P0 事件落库；支付转化以回调为准；事件无 PII |
| 日志 | 请求日志不含完整手机号、token |
| 依赖 | 提交 `package-lock.json`；禁止无 lock 安装 |

升级依赖时必须在 16.17.0 重装验证，禁止只在 Node 18 开发后提交。
