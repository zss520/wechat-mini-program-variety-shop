## 1. 小程序信息架构

### 1.1 页面清单

| 页面 | 路径建议 | 说明 |

| 分类 | `pages/category/index` | 左分类右商品 |

| 地址列表 / 编辑 | `pages/address/list` `pages/address/edit` | |
| 个人中心 | `pages/mine/index` | |
| 店铺信息 / 联系 | `pages/shop/index` | 可选，可做弹层 |

### 1.2 TabBar（建议）

| Tab | TDesign 图标 | 跳转 |
|-----|-------------|------|
| 首页 | `home` | 首页 |
| 分类 | `view-module` | 分类 |
| 购物车 | `cart` | 购物车 |
| 我的 | `user` | 个人中心 |

底部使用 TDesign `TabBar`（微信自定义 tabBar），不再使用本地 PNG 作为可见图标。

订单从「我的」进入，避免 Tab 超过 4 个导致拥挤。若产品坚持 5 Tab，可将「订单」独立，但图标与字号仍需照顾老年用户。

### 1.3 全局

- 启动：读取店铺配置（名称、主题色、配送开关），缓存至 `globalData` + `Storage`，TTL 建议 5 分钟。
- 登录态：`token` 存 Storage；401 清 token 并引导登录，不打断浏览（浏览可匿名，**下单 / 加购同步 / 订单必须登录**）。加购：未登录可先写入本地车，登录后合并（P1）；P0 可简化为加购即登录。
- **P0 简化决策：加入购物车、立即购买、进入购物车结算必须已登录。** 浏览、搜索、详情可匿名。
- **埋点：** 全局 `tracker.track`；商品卡组件内完成曝光观察与点击；`App.onHide` flush 队列。匿名可上报。实现细节见文档 07。

## 2. 小程序页面规格

### 2.1 首页

**展示模块（自上而下）：**

1. 导航栏标题 = 店铺名称（可自定义导航）。
2. 搜索条（只读跳转搜索页）。
3. 轮播：`autoplay` 4s，指示点，0 张则整块不渲染。
4. 分类导航：最多一屏 8–10 个，图标 + 文字，超出换行；点击进入分类页并选中该项。
5. 履约提示条：如「本店支持到店自提；配送 19:00 前下单当天送」（文案拼配置）。
6. 特价专区：横滑或 2 列网格，商品卡同列表卡。
7. 推荐 / 热销：纵向网格。数据来自首页推荐位算法（P1；P0 可暂按 `sort`+销量，但卡片仍须带 `slot_id=home_recommend` 以便埋点）。点击进入详情时 URL 带 `slot` 与 `pos`。

**商品卡字段：** 封面、名称（最多 2 行省略）、价格（现价强调，原价删除线若有特价）、单位（如 `/袋`）、售罄遮罩。

**商品卡埋点（强制）：** 使用统一组件。`IntersectionObserver` 50% 可见且 ≥300ms 触发 `goods_expose`；点击触发 `goods_click`。禁止列表接口返回即曝光。

**空态：** 店铺无上架商品时展示「店主正在上架」+ 联系店主按钮。

**下拉刷新：** 刷新配置与首页聚合接口。

### 2.2 搜索

- 进入聚焦输入框；支持键盘搜索。
- 展示历史（本地，最多 10 条），可清空。
- 结果页：与商品列表同一卡片组件；无结果提示换词 + 去分类逛。
- 搜索范围：上架商品的名称、副标题；一期不搜详情正文。

### 2.3 分类页

- 左侧分类：含「全部」。
- 右侧：当前分类商品，分页上拉加载。
- 排序：综合（默认，`heat_score + manual_weight`，售罄沉底）、价格升/降、销量、上新。顾客端不展示「热度」选项。
- 切换分类重置列表。

### 2.4 商品详情

| 区域 | 内容 |
|------|------|
| 图集 | 滑动多图；无图占位 |
| 价格栏 | 现价、单位、已售（可选）、库存「有货 / 仅剩 N 件 / 售罄」（N 阈值默认 10） |
| 标题 | 名称 + 副标题 |
| 规格 | 一期仅数量步进器，步长 1，最小 1，最大 `min(库存, 限购)`，限购默认 99 |
| 详情 | 富文本或图片详情；空则隐藏块 |
| 底栏 | 购物车入口（带数量）、加入购物车、立即购买；售罄时主按钮禁用 |

**立即购买：** 生成临时结算行（不经过购物车表），进入确认订单，`from=buy_now`。上报 `buy_now_click`。

**分享（P1）：** `onShareAppMessage` 标题为商品名，path 带 id 与 `from=share`。上报 `share_click`。

详情 `onShow` 上报 `goods_detail_view`（`from_slot` 取 query）。

### 2.5 购物车

- 按登录用户拉服务端购物车。
- 每行：勾选、图、名、价、步进器、删除。
- 失效（下架或库存 0）：取消勾选、禁用步进、展示「已失效」，提供「删除」。
- 底部：全选、合计（仅勾选有效商品）、去结算（件数）。
- 结算前再次校验库存与上架状态，失败停留本页并 Toast 原因。

### 2.6 确认订单

**区块：**

1. 履约方式：`自提` / `配送`（Segmented）。店铺关闭配送则仅自提。
2. 自提：展示地址、电话、营业时间，不选地址。
3. 配送：展示默认地址，可跳转地址列表；无地址引导新增。P1 配送范围校验。
4. 商品清单：缩略图、名、数量、单价、小计。
5. 配送费行（仅配送）。
6. 备注：可选，最多 80 字。
7. 应付合计。
8. 提交订单并支付。

**提交失败：** 库存不足、商品下架、未授权手机号、配送未选地址、店铺休息（若配置暂停接单）。

**支付：** 调起微信支付。用户取消支付：订单已创建为待付款，跳转订单详情并提示「可继续支付」。

### 2.7 订单列表 / 详情

**Tab：** 全部 / 待付款 / 待备货 / 待取货或配送中 / 已完成 / 已取消。

「待取货或配送中」可合并为「进行中」，详情里区分。

**详情必须有：**

- 状态时间线（至少：下单、支付、备货、完成 / 取消）。
- 商品行、金额明细（货款、运费、优惠、实付）。
- 履约信息：自提码（待自提时放大）、配送地址。
- 操作：待付款-去支付 / 取消；待备货-取消并退款；进行中-联系店主；完成-再买一单（P1）。

**自提码：** 6 位数字或短码，店主核销用；同时生成条码 / 二维码更佳（P1），P0 数字码即可。

### 2.8 地址

字段：联系人、手机、省市区、详细地址、默认与否。一期可用「城市 + 小区 / 门牌」自由文本降低选区组件成本，但建议仍用微信 `chooseAddress` 填充。

### 2.9 个人中心

- 头像昵称：未登录显示「点击登录」。
- 订单四宫格：待付款、待备货、待取货、已完成（数字角标 P1）。
- 地址管理、联系店主（`phone` 拨号、微信号复制）。
- 会员 / 券入口无数据配置时隐藏。

### 2.10 登录与授权

符合现行微信小程序登录规范：

1. `wx.login` 获取 `code`，服务端 `code2session`，签发业务 token。
2. 头像昵称：使用微信提供的选择器 / 头像昵称填写能力，禁止违规获取。
3. 手机号：使用手机号快速验证组件，**下单前必须绑定**（PRD 默认）。
4. 隐私协议：首次弹出同意（上线材料）。

### 3.3 登录页

- 居中 Card：店铺系统名、账号、密码、登录按钮。
- 错误：账号或密码错误统一文案，不暴露是否存在用户。
- 连续失败锁定（P1）：如 5 次 / 15 分钟。

### 3.4 商品列表

**筛选：** 名称关键词、分类、上架状态。

**列：** 封面缩略图、名称、分类、价格、库存、状态、更新时间、操作（编辑、上架/下架、删除）。

**删除：** 仅允许无「进行中订单占用」或改为「归档不下架删除」（P0 采用 **软删除**：下架且 `deleted_at`，列表默认不展示）。已有历史订单的商品不可物理删除。

**新建 / 编辑表单：**

| 字段 | 必填 | 校验 |
|------|------|------|
| 名称 | 是 | 1–40 字 |
| 副标题 | 否 | ≤ 80 字 |
| 分类 | 是 | 已启用分类 |
| 价格（元） | 是 | > 0，最多 2 位小数 |
| 单位 | 是 | 如 件 / 袋 / 瓶，≤ 8 字 |
| 库存 | 是 | 整数 ≥ 0 |
| 主图 | 是 | 图片，建议 ≤ 2MB，jpg/png/webp |
| 附图 | 否 | 最多 8 张 |
| 详情 | 否 | 文本或简单富文本（P0 可用多行文本 + 详情图） |
| 上架 | 是 | 开关，默认上架 |
| 排序值 | 否 | 整数，越大越前（综合排序的最后兜底） |
| 排序加权 | 否 | P1，-50～50，默认 0；文案勿写成「热度」 |

提交成功返回列表；校验失败字段下红字（MUI `TextField` helperText）。

商品列表 P1 可选列：热度、7 日 CTR、7 日购买率、加权；行内改加权。样本不足显示「—」。

### 3.5 分类

- 表格：名称、排序、商品数、启用、操作。
- 删除：分类下仍有未删除商品时禁止，提示先移动商品。
- 排序影响小程序分类导航与默认综合排序的次级因子。

### 3.6 订单列表与详情

**筛选：** 状态下拉、下单时间范围、订单号、手机号。

**列：** 订单号、下单时间、顾客（昵称 + 脱敏手机）、实付、履约方式、状态、操作。

**行操作随状态变化：**

| 状态 | 店主操作 |
|------|----------|
| 待付款 | 查看；一般不处理（可店主关闭） |
| 待备货 | 备货完成；取消并退款（确认框输入原因可选） |
| 待自提 | 核销（输入提货码，默认填入该单码）；联系 |
| 配送中 | 确认送达 |
| 待备货且配送单 | 备货完成后进入「待配送」，再「开始配送」 |

**核销校验：** 码必须匹配该订单且状态为待自提。错误码明确提示。

**详情页：** 完整商品表（名称、单价、数量、小计）、优惠与运费、用户备注（高亮）、地址、支付流水号（只读）。

**待处理强调：** 工作台与侧栏订单菜单可显示 Badge（待备货 + 待自提数量）。

### 3.7 轮播管理

- 列表：预览图、标题、跳转类型（无 / 商品 / 分类 / 小程序路径）、排序、启用。
- 最多 5 条启用；超出禁止再启用并提示。

### 3.8 店铺设置

分组：基础信息、联系方式、自提、配送、交易（超时分钟、是否暂停接单）。

保存后小程序在缓存 TTL 内更新。暂停接单：小程序可浏览不可提交订单，提示「店主休息中」。

### 3.9 交互通则（管理端）

- 破坏性操作：`Dialog` 二次确认。
- 成功 / 失败：`Snackbar` + `Alert`。
- 列表加载：`Table` 上 `LinearProgress` 或骨架。
- 按钮在提交中 `disabled` + `CircularProgress`，防止重复提交。
- 中文：所有用户可见文案简体中文；代码与 REST 路径英文。

### 3.10 推荐位（P1）

- 路由 `/contents/recommends`：选择 `home_recommend`，设置容量与策略，置顶列表（上移/下移/删除/搜索添加）。
- 「预览」调用 preview 接口，只读展示将出现在小程序的 N 个商品。
- 售罄置顶项标警告，保存时按默认跳过（D7）。
- 布局：左配置表单，右预览列表；符合 MUI 双栏。

### 3.11 商品分析（P1）

- 路由 `/reports/goods`：时间窗、分类、快捷筛「高曝光低转化」。
- 列：曝光 UV、CTR、加购率、购买率、支付件数/金额、热度、加权。
- 率值样本不足灰色「样本少」；可跳转改加权或去推荐位置顶。

## 4. 订单状态机

```
                    超时 / 顾客取消
  [创建] → 待付款 ─────────────────────→ 已取消
              │ 支付成功
              ▼
           待备货 ──店主退款取消──────→ 已取消（退款中/已退款可作子状态，P0 合并已取消）
              │ 备货完成
              ├── 自提 ──→ 待自提 ──核销──→ 已完成
              └── 配送 ──→ 待配送 ──开始配送──→ 配送中 ──送达──→ 已完成
```

**展示映射（顾客端文案）：**

| 内部状态 | 顾客文案 |
|----------|----------|
| `PENDING_PAY` | 待付款 |
| `PENDING_PACK` | 商家备货中 |
| `WAIT_PICKUP` | 待取货 |
| `WAIT_DELIVER` | 待配送 |
| `DELIVERING` | 配送中 |
| `COMPLETED` | 已完成 |
| `CANCELLED` | 已取消 |
| `REFUNDING` | 退款中（若独立；否则仍显示已取消并备注退款） |

非法流转必须被服务端拒绝（例如待付款直接核销）。

## 5. 购物车与库存并发

1. 加购：数量累加，不超过库存。
2. 下单：对选中 SKU 开启事务：校验上架与库存 → 写订单行 → 扣减 **可售库存**（预占）→ 清空已下单购物车行。
3. 支付成功：预占转为已售（若模型将库存单一字段，则预占时已减 `stock`，取消时加回）。
4. **推荐模型：** `stock` 为可售；下单减 `stock`，取消/超时加回。支付成功不再减第二次。

超卖保护：更新语句 `WHERE stock >= :qty`，影响行数为 0 则失败回滚。

## 9. P1 功能规格要点（不展开交互稿）

- **优惠券：** 满减（满 M 减 N）、折扣（打 D 折封顶可选）；每人限领；下单选择一张；与特价叠加规则默认 **不叠加，取更优或仅券**（待决，默认不叠加特价，可叠加满减券）。
- **积分：** 实付 1 元 = 1 分；100 分抵 1 元（示例，数值可配）；下单勾选抵扣。
- **限时特价：** 商品维度 `special_price` + 时间窗；列表展示划线价。
- **库存预警：** 阈值默认 5，工作台列表。
- **批量改价：** 按百分比或固定额，预览后确认。
- **商品分析 / 权重 / 首页推荐位：** 以 [文档 07](./07-埋点与商品运营分析.md) 为准，本规格仅补页面与组件约束。

P2（拼团、秒杀、标签、日报、详情关联推荐、购物车凑单）仅保留导航隐藏或「即将推出」，不在一期实现。
