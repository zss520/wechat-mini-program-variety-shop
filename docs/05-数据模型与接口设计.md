# 杂货铺微信小程序 · 数据模型与接口设计

| 项 | 内容 |
|----|------|
| 文档版本 | V1.1 |
| 风格 | REST、JSON、UTF-8、金额 **整数分** |

基础路径：`/api`。管理端前缀 `/api/admin`，小程序前缀 `/api/app`（或同域按 token 角色区分；**推荐路径隔离**，避免鉴权疏漏）。

---

## 1. 通用约定

### 1.1 响应包

成功：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

失败：`code != 0`，HTTP 仍可用 200（小程序好处理）或 4xx；**统一用 HTTP 状态 + body.code**。建议：

| HTTP | 场景 |
|------|------|
| 200 | 业务成功 |
| 400 | 参数错误 |
| 401 | 未登录 / token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 状态冲突（如库存不足、非法流转） |
| 500 | 未处理异常 |

`code` 业务码示例：`10001` 库存不足，`10002` 商品已下架，`10003` 订单状态不允许，`10004` 提货码错误。

### 1.2 鉴权头

`Authorization: Bearer <token>`

管理端与小程序签发不同类型或在 payload 中带 `role: admin | user`，校验时必须核对路径。

### 1.3 分页

Query：`page` 从 1，`pageSize` 默认 20，最大 100。

返回：`{ list, page, pageSize, total }`。

### 1.4 时间

ISO 8601 字符串，时区 **Asia/Shanghai** 或统一 UTC 并在文档注明；建议存 UTC，展示转东八区。

## 2. 核心实体

### 2.1 ER 关系（逻辑）

```
ShopSettings (单行配置)
AdminUser 1──n（无强关联商品）

Category 1──n Goods
User 1──n Address
User 1──n CartItem n──1 Goods
User 1──n Order 1──n OrderItem n──1 Goods
Order 1──0..1 Payment
Order 1──0..n OrderLog
Banner
RecommendSlot 1──n RecommendSlotItem n──1 Goods
AnalyticsEvent
GoodsStatsDaily
```

已建：`Coupon`、`UserCoupon`、`PointsLedger`、`group_buy_*`、`seckill_activities`、`user_subscribes`、`notify_logs`。商品含 `special_price_cent` 时间窗。订单含券/积分/活动字段。

## 4. 小程序 API（`/api/app`）

除标注外均需顾客 token。

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/shop/bootstrap` | 否 | 店铺名、主题、配送开关、暂停接单、分类摘要 |
| POST | `/auth/wx-login` | 否 | `{ code }` → token + user |
| POST | `/auth/wx-phone` | 是 | 绑定手机号 |
| GET | `/home` | 否 | 按首页展示块返回：`banner` / `seckill` / `group` / `deal` / `forYou` / `recommend`，每块含 `key` `title` `list` |
| GET | `/categories` | 否 | 启用分类 |
| GET | `/goods` | 否 | query: categoryId, keyword, sort=`composite\|price_asc\|price_desc\|sales\|new`, page |
| GET | `/goods/:id` | 否 | 详情；下架对顾客 404 |
| POST | `/events` | 否 | 批量埋点 `{ events: [] }`；有 token 则绑定 user_id |
| GET | `/cart` | 是 | 列表（含失效标记） |
| POST | `/cart` | 是 | `{ goodsId, qty }` 加购或变更 |
| DELETE | `/cart/:id` | 是 | 删除行 |
| PUT | `/cart/select` | 是 | 可选，若勾选存服务端 |
| GET | `/addresses` | 是 | |
| POST | `/addresses` | 是 | |
| PUT | `/addresses/:id` | 是 | |
| DELETE | `/addresses/:id` | 是 | |
| POST | `/orders/preview` | 是 | 结算预览：金额、库存校验 |
| POST | `/orders` | 是 | 创建订单（待付款） |
| GET | `/orders` | 是 | 我的订单 |
| GET | `/orders/:id` | 是 | 仅自己的 |
| POST | `/orders/:id/pay` | 是 | 返回 `wx.requestPayment` 参数 |
| POST | `/orders/:id/cancel` | 是 | 规则内取消 |
| POST | `/orders/:id/rebuy` | 是 | P1 再买 |

**GET `/home` 按首页展示块拆分（每块 `key` + `title` + `list`）：**

```json
{
  "banner": { "key": "banner", "title": "", "list": [] },
  "seckill": { "key": "seckill", "title": "限时秒杀", "list": [] },
  "group": { "key": "group", "title": "拼团", "list": [] },
  "deal": { "key": "deal", "title": "特价专区", "list": [] },
  "forYou": { "key": "forYou", "title": "为你推荐", "list": [] },
  "recommend": { "key": "recommend", "title": "本店推荐", "slotId": "home_recommend", "list": [] }
}
```

秒杀项额外带 `remainMs`。空块仍返回，`list` 为 `[]`，小程序按长度决定是否渲染。

**创建订单 body 示例：**

```json
{
  "fulfillType": "PICKUP",
  "addressId": null,
  "remark": "",
  "items": [{ "goodsId": 1, "qty": 2 }],
  "from": "CART"
}
```

`from=BUY_NOW` 时 items 为立即购买行。

**支付返回（小程序）：** `timeStamp, nonceStr, package, signType, paySign`。

微信支付 **回调** 不走 `/api/app`，而为 `/api/pay/wechat/notify`（验签、幂等）。

## 6. 关键校验规则（接口层必须重复校验）

1. 顾客创建订单：`pause_order` 为真则 409。
2. 每件商品 `on_sale=1` 且 `deleted_at` 空且 `stock >= qty`。
3. `pay_amount` 服务端重算，与预览差超过 0 则 409「价格变化，请刷新」。
4. 配送：`delivery_enabled` 且 `addressId` 有效且属于该用户。
5. 核销：`pickup_code` 恒等匹配、状态 `WAIT_PICKUP`。
6. 退款：调微信退款 API 成功后再改订单；失败保持原状态并报错。
7. 埋点：`event` 必须在字典内；单次 ≤20 条；`payload` 剥离手机号/openid；超限丢弃并计数。
8. `manual_weight` 超出 -50～50 则 400。
9. 推荐位置顶条数不得超过 `capacity`；`goods_id` 须未删除。
10. 支付成功必须同步增加当日 `goods_stats_daily` 的支付指标（或写内部事件再聚合），不得只靠客户端。

## 7. 编号与提货码

- `order_no`：`yyyyMMdd` + 6 位当日流水或雪花，保证唯一。
- `pickup_code`：6 位数字，避免 `0` 开头混淆可从 `100000–999999` 随机，单日未完成订单内唯一。

---

## 8. 脱敏

管理端列表手机号：`138****1234`。导出（P2）需权限。日志禁止打印完整 token、微信支付密钥。`analytics_events` 禁止出现 openid、手机号、详细地址。
