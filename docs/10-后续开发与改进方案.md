## 1. 当前基线（保持，不重做）

开发版已能在 `MOCK_WX` / `MOCK_PAY` 下走完浏览、下单、模拟支付、备货、自提核销和配送状态。下面这些能力已经在代码里，后续改动只修缺陷或补缺口，不换技术栈、不推倒重来。

| 域 | 已有能力 |
|----|----------|
| 货架 | 分类、商品、多图与缩略图、上下架、特价时段、综合/价格/销量/上新排序 |
| 交易 | 购物车勾选、确认订单、库存条件扣减、待付款关单、提货码、地址 |
| 营销 | 满减/折扣券（领取、店主发放、领取明细）、积分流水、拼团（按已支付人数）、秒杀 |
| 用券 | 列表展示有效开始、有效结束、使用门槛；确认订单只列出满足时间、门槛、叠加规则的券 |
| 内容 | 轮播（最多启用 5 张，分类选商品跳转）、通知公告（最多启用 20 条，跳转规则同轮播）、店铺设置 |
| 运营 | 曝光/点击埋点、热度日批、漏斗与会员画像、推荐位置顶后按热度补齐 |
| 体验 | 管理端金额按元录入（库存仍为分）、列表分页、苹方字体、搜索页、真机把 `127.0.0.1` 图片改写到局域网地址 |

技术约束继续有效：顾客端微信原生（WXML/WXSS/TS，TDesign），管理端 Vite 4.5 + React 18.2 + MUI v5.15，服务端 Node 16.17.0 + Express 4 + knex + MySQL 8。单店。金额存分，下单金额服务端重算。

## 2. 改进原则

1. **先让真机能稳定用，再谈正式审核。** 云端环境没有微信开发者工具，小程序改动必须在本机开发者工具和真机上按第 6 节清单点过，再算完成。
2. **开业门禁与功能迭代分开。** 域名、类目、支付进件依赖店主资质，不阻塞开发版里的体验和数据修复。
3. **一条改动只解决一个店主或顾客能感知的问题。** 不把 Node 升级、文档补表、界面微调捆进同一个提交。
4. **规则以服务端为准。** 小程序筛选优惠券、展示公告，只是少展示不该用的数据；提交订单、核销、发券仍由接口拒绝非法状态。
5. **订阅通知和店铺公告继续分家。** `notify_logs` 是备货订阅记录；`announcements` 是店主发布的公告。不要合成一张表。

| 切片 | 目标 | 是否依赖微信资质 |
|------|------|------------------|

## 4. 改进项

### 4.1 N1 真机收口

**现状。** `miniprogram/utils/config.ts` 把接口和文件域名写成固定局域网 IP。图片加载会把 `127.0.0.1` 改写到这个 IP。换网络后真机仍会出现图片叉和请求失败。首页公告、券列表、确认订单的可用券筛选，只在接口和浏览器管理端验证过。

**改法。**

- 开发期把 API / 文件根地址收成一处配置，并在 README 写明：开发者工具与真机必须指向同一台正在跑的 API，不能一个用 `127.0.0.1`、一个用局域网 IP。
- 保留「回环地址改写成文件根地址」的逻辑，避免服务端 `PUBLIC_URL` 仍是 `127.0.0.1` 时真机裂图。
- 首页公告：多条时纵向轮播，点击内容打开**当前这一条**（可跳转进商品，否则进详情）；点右侧箭头进入公告列表。单条时横向滚动标题。
- 券列表同时展示面额或折扣（例如满减「减 ¥5」、折扣「9 折」），与已有的开始时间、结束时间、门槛放在同一张卡片里，避免只看见门槛看不见优惠力度。

**验收。**

- 修改配置里的主机后，首页商品图、轮播图、详情图在真机可打开。
- 未开始、已过期、未满门槛、以及折扣券遇到特价/拼团/秒杀时，确认订单的选择器里没有这些券；接口在强行带上券 id 时返回业务错误，订单不创建。
- 后台同时启用两条公告（一条不跳转、一条跳商品），真机首页能轮播标题，两条的点击去向与后台配置一致。

### 4.2 N2 营销与履约补缺

#### 4.2.1 优惠券规则写死在测试里

**现状。** 小程序 `usableCoupons` 与服务端 `loadUsableCoupon` 各自判断门槛、时间和折扣叠加。列表测试覆盖了前端函数，缺少「预览金额不够时创建订单必须失败」的接口测试。

**改法。** 在现有 `marketing` 测试上补一条：商品金额低于 `min_amount_cent` 时 `preview` 与 `create` 都不核销该券。前端文案继续用「暂无满足门槛的优惠券」和「暂无可用优惠券」区分原因。

**验收。** `npm test` 在测试库上失败即退出；通过时该用例打印在 marketing 结果里。

#### 4.2.2 备货订阅真正发出

**现状。** 顾客在「我的」打开备货通知后，只写入 `user_subscribes`。店主点备货时 `notifyPackReady` 往 `notify_logs` 插入一行，状态直接标 `SENT`，没有调用微信订阅消息接口。后台「订阅通知」看到的是日志，不是微信是否送达。

**改法。**

- 配置模板 ID 与跳转页（订单详情）后，备货成功且用户已接受订阅时调用发送接口。
- 微信返回失败、未配置模板、用户拒绝时，日志状态分别为失败或跳过，**订单状态仍然变成待自提**。
- 未配置模板时保持现在的记录行为，避免开发环境报错打断备货。

**验收。** 有模板且用户接受时，微信能收到「请来取货」和提货码；无模板时订单仍能核销，日志不是虚假的成功（无模板标跳过）。

#### 4.2.3 库存预警可处理

**现状。** 工作台有「库存预警」数字。店主不能从这里直接看到是哪些商品、也不能去改库存。

**改法。** 预警阈值沿用现有字段。工作台数字链到商品列表，并带上「库存低于阈值」筛选。列表里这些行可进编辑改库存。

**验收。** 把一件商品库存改到阈值以下，工作台数量加一；点进去只看到这批商品；改回阈值以上后数字减少。

#### 4.2.4 订单导出

**现状。** 后台可以搜订单、看详情、走履约。没有按日导出，店主对账仍要逐条抄。

**改法。** 订单列表增加导出当前筛选结果（CSV）：订单号、状态、履约方式、应付（元）、提货码或地址摘要、下单时间。导出上限与分页无关，单次最多 2000 行，超出提示缩小时间范围。金额在导出时由分换算成元，库内仍存分。

**验收。** 筛选「今日已支付」导出的行数与列表总数一致，金额与详情页一致。

#### 4.2.5 配送范围先做人工说明

**现状。** 关闭配送后确认订单只剩自提。没有「超出配送范围」的判断。PRD 里的 LBS / 小区名单仍是 P1，不做骑手调度。

**改法。** 店铺设置增加一段「配送说明」（纯文本，例如配送小区或起送说明）。确认订单选择配送时展示这段文字。不在本阶段做地图测距。

**验收。** 填写说明后，小程序配送确认页能看到同一段文字；留空则不占一行。

### 4.3 N3 文档与本机库

**现状。** `docs/05` 和根 README 仍按早期表数量描述。`announcements`、券发放来源、积分流水是后续迁移加的。本机若只导入旧的 `scripts/variety_shop.sql`，会缺表，小程序公告接口和后台通知公告会报错。

**改法。**

- 在 `docs/05` 补公告表、公开接口 `GET /api/app/home/announcements`、`GET /api/app/announcements/:id`，以及管理端公告 CRUD。注明与 `/notices`（订阅日志）不是同一资源。
- 重新生成或追加本机导入脚本，使「导入 SQL」和 `knex migrate:latest` 得到同一套表。README 改为「以迁移为准」，不再写死 18 张表。
- `docs/09` 的「本机应签出分支」改为当前日常分支 `user/zss`。

**验收。** 空库只执行 README 中的导入或 `npm run migrate && npm run seed` 后，管理端能打开通知公告，小程序 `GET /home/announcements` 返回 `key=announcement`。

### 4.4 N4 开业门禁

本段对应 [08 的 M6](./08-项目开发计划.md) 和 [06 第 1.6、2.1 节](./06-非功能需求与实施计划.md)。功能冻结，只做能提交审核和收款的事项。

| 项 | 完成标准 |
|----|----------|
| 模拟开关 | 生产 `.env` 中 `MOCK_WX=false`、`MOCK_PAY=false`。未配置商户号时下单返回明确错误，不假装支付成功 |
| 登录 | 真机 `wx.login` + 手机号组件；隐私协议说明收集手机号、地址、订单，以及用于货架分析的行为数据（不含手机号和 openid） |
| 域名 | request、uploadFile、downloadFile 合法域名指向 HTTPS；小程序不再依赖「不校验合法域名」 |
| 支付 | 商户号绑定 AppID `wx6434c5c04d4b6c6e`；回调 `POST /api/pay/wechat/notify` 验签、幂等；支付成功后杀进程，销量仍增加 |
| 部署 | Nginx 托管管理端静态文件并反代 `/api`；进程守护；MySQL 每日备份并可恢复到演练库 |
| 手测 | 06 §2.1 的上架→支付→备货→核销、超时关单、待备货取消回库存、1 件库存并发只有一单成功 |

审核材料（类目、执照、用户隐私保护指引）由店主在公众平台提交。研发提供隐私页正文和域名检查结果。

### 4.5 N5 技术债（单独排期）

| 项 | 现状 | 改法 | 不在本项做的事 |
|----|------|------|----------------|
| 持续集成 | 测试靠本机 `server` 的 `npm test` | 在 Node 16.17.0 镜像跑服务端测试和管理端 `tsc --noEmit` | 不升级 Vite |
| 密钥 | 示例 JWT 密钥和 `cors origin: true` 适合开发 | 生产强制独立 `JWT_SECRET`；管理端来源限制到店主域名 | 不重做登录 |
| Node 16 | 已停止官方维护，文档已记录 | 单开评估：先在拷贝环境用 Node 18 跑通 `admin build` 与 `server test`，通过后再改 `engines` | 不与优惠券、公告、支付进件混在一次发布 |
| 管理端测试 | 无组件测试 | 先保持浏览器手测登录、商品保存、公告发布、订单备货。接口测试继续加在 `server/src/tests` | 不引入新测试框架，除非 N5 单独决定 |

## 5. 实施顺序

| 序号 | 包 | 依赖 | 退出条件 |
|------|----|------|----------|
| 1 | N1 地址配置与真机清单 | 无 | 第 6 节清单在真机勾完 |
| 2 | N2.1 用券接口测试 | 无，可与 1 并行 | 测试库 `npm test` 通过 |
| 3 | N2.3 库存预警跳转、N2.4 订单导出、N2.5 配送说明 | 无 | 管理端浏览器走通；小程序看到配送说明 |
| 4 | N3 文档与导入脚本 | 无 | 空库导入后公告接口可用 |

同一序号里，服务端契约先于管理端和小程序。公告、优惠券、轮播的已有页面只做增量，不调整已经合入的间距、分页和搜索样式，除非真机清单指出具体错位。

## 6. 真机手测清单（N1 门禁）

在微信开发者工具勾选不校验合法域名的前提下，用真机预览再做一遍。云端代理无法代替。

1. 首页：商品图、轮播图不是叉；有公告时能看到标题；两条公告切换后点进去是当前条。
2. 搜索：输入、历史、结果图正常。
3. 分类、详情、加购、购物车勾选金额与结算一致。
4. 领券列表能看见门槛和开始/结束时间；我的券三个状态筛选正确。
5. 确认订单：金额未满门槛时选不到该券；满门槛后可选，应付减少额与券面一致。
6. 拼团详情进度按已支付人数；秒杀能进确认订单。
7. 我的：订单、券、积分、公告、店铺电话与后台设置一致。
8. 管理端（桌面浏览器）：通知公告发布两条、一条跳商品；商品价格以元保存后小程序显示同一金额。
